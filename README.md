# ⭐ Telegram Stars Bot — бот для продажи Звёзд Телеграм (open-source)

**Готовый open-source бот и шаблон магазина для продажи Telegram Stars (Звёзд
Телеграм) с вашей наценкой.** Пользователь указывает `@username` получателя и
количество звёзд, оплачивает **картой, через СБП или криптой (TON)**, а звёзды
доставляются автоматически. По сути — готовый скрипт для автопродажи Telegram
Stars, который вы разворачиваете на своём сервере за 30–40 минут по
[пошаговому гайду](#-установка-по-шагам-для-новичков). Приём платежей и выдача
звёзд — через **WATA** (карта/СБП) и **GreenGamePay** (TON). Интерфейс на
**русском и английском** с переключением на лету.

|---|---|---|
| ⭐ | **Продажа Telegram Stars** | Покупка звёзд для любого @username (от 50 до 50 000) через WATA Digital Goods API |

| 🧩 | **Партнёрские боты** | Партнёр создаёт своего бота (Telegram managed bots) прямо в боте, сам задаёт наценку (до `50% − MARKUP_PERCENT`) и зарабатывает её с продаж; вы удерживаете `PARTNER_COMMISSION_PERCENT`% от его наценки; всё хостится у вас (multibot) |

## 🚀 Установка по шагам (для новичков)

> Никогда не работали с сервером? Ничего страшного — просто повторяйте шаги по
> порядку. Весь процесс занимает **~30–40 минут**. Всё, что нужно ввести в
> терминал, лежит в блоках `вот так` — их можно копировать целиком.
>
> **Уже опытный?** Коротко: арендуйте VPS, направьте домен на его IP, выполните
> `curl -fsSL https://raw.githubusercontent.com/evansvl/telegram-stars-bot/main/scripts/install.sh | bash`,
> заполните `.env` (`BOT_TOKEN`, `WATA_TOKEN`, `WEBHOOK_HOST`, `ADMIN_IDS`),
> поднимите Caddy на `127.0.0.1:8080`, перезапустите. Детали — ниже.

### Что понадобится

- Аккаунт **Telegram**.
- **Сервер (VPS)** на Linux — от ~200 ₽/мес (шаг 3).
- **Домен** — от ~150 ₽/год или бесплатный поддомен (шаг 4).
- Доступ к **WATA** для приёма оплаты картой (шаг 2).

---

### Шаг 1. Создаём бота в Telegram → `BOT_TOKEN`

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте `/newbot`, придумайте имя и `username` (должен заканчиваться на `bot`).
3. BotFather пришлёт **токен** вида `123456789:AAE-Ct...` — скопируйте его.

> 🔒 Токен — это пароль от бота. Никому не показывайте и не публикуйте.

---

### Шаг 2. Получаем доступ к WATA → `WATA_TOKEN`

Через WATA бот принимает оплату картой/СБП и выдаёт звёзды (депозит не нужен).

1. Зарегистрируйтесь на [merchant.wata.pro](https://merchant.wata.pro/login) и
   подключите продукт **«Telegram Stars + Эквайринг»**.
2. В личном кабинете найдите **API-токен** — это `WATA_TOKEN`.

> Для тестов есть песочница [merchant-sandbox.wata.pro](https://merchant-sandbox.wata.pro/)
> (доступ выдаёт менеджер WATA).

---

### Шаг 3. Арендуем сервер (VPS)

Боту нужен **Linux-VPS** с публичным IP. Подойдёт любой провайдер; мы используем
**[Aeza](https://aeza.net/?ref=613643)** — по [этой ссылке](https://aeza.net/?ref=613643)
вы заодно поддержите проект 💚

- ОС: **Ubuntu 22.04+** (или Debian 12+).
- Тариф: **1 vCPU, 1 ГБ RAM, 10 ГБ** диска — хватит с запасом.
- Порты **80 и 443** должны быть открыты.

После создания запишите **IP-адрес** сервера и **пароль root** (из письма или панели).

---

### Шаг 4. Привязываем домен

Telegram шлёт обновления только по **HTTPS**, а для него нужен домен.

1. Купите домен (например, [reg.ru](https://www.reg.ru)) или возьмите бесплатный
   поддомен (например, [duckdns.org](https://www.duckdns.org)).
2. В настройках DNS создайте **A-запись**: имя `bot`, значение — **IP вашего
   сервера** из шага 3. Получится, например, `bot.ваш-домен.ру → 12.34.56.78`.
3. Подождите 5–30 минут, пока запись обновится.

Запомните адрес `bot.ваш-домен.ру` — это ваш **`WEBHOOK_HOST`**.

---

### Шаг 5. Подключаемся к серверу по SSH

- **Windows:** откройте **PowerShell** (или «Терминал») и введите:
  ```powershell
  ssh root@IP-адрес-сервера
  ```
- **macOS / Linux:** откройте «Терминал» и введите то же самое.

При первом подключении спросит `yes/no` — введите `yes`. Затем введите пароль root
(символы при вводе **не отображаются** — это нормально, просто печатайте и жмите Enter).

---

### Шаг 6. Устанавливаем бота одной командой

Уже на сервере выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/evansvl/telegram-stars-bot/main/scripts/install.sh -o install.sh
bash install.sh
```

Скрипт сам установит Docker, скачает проект и создаст файл настроек `.env`. В конце
он напишет: *«отредактируйте .env и запустите скрипт снова»* — так и сделаем.

---

### Шаг 7. Заполняем настройки — файл `.env`

Откройте файл в редакторе:

```bash
cd telegram-stars-bot
nano .env
```

Впишите как минимум эти строки (остальные можно не трогать):

```dotenv
BOT_TOKEN=123456789:AAE...           # из шага 1
WATA_TOKEN=ваш-токен-wata            # из шага 2
WEBHOOK_HOST=bot.ваш-домен.ру        # из шага 4 (без https:// и без / в конце)
ADMIN_IDS=123456789                  # ваш Telegram ID (см. ниже)
MARKUP_PERCENT=20                    # ваша наценка в %
```

**Как узнать свой Telegram ID:** напишите [@userinfobot](https://t.me/userinfobot) —
он пришлёт ваше число.

Сохранить в `nano`: **Ctrl+O** → **Enter**, выйти: **Ctrl+X**.

> 💎 Оплату криптой (TON) можно включить позже — см. блок
> «(Опционально) Оплата криптой (TON)» ниже.

### Шаг 8. Включаем HTTPS (обязательно)

Telegram принимает вебхуки только по HTTPS. Самый простой способ — **Caddy**: он сам
получит и продлит SSL-сертификат.

```bash
# установка Caddy (Ubuntu/Debian)
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy
```

Откройте конфиг командой `sudo nano /etc/caddy/Caddyfile` и впишите (замените домен
на свой):

```caddyfile
bot.ваш-домен.ру {
    reverse_proxy 127.0.0.1:8080
}
```

Примените: `sudo systemctl reload caddy`.

> Подробнее (и вариант на Nginx) — в разделе [🌐 Reverse proxy и HTTPS](#-reverse-proxy-и-https).

### (Опционально) Оплата криптой (TON)

**Где регистрироваться:** заведите аккаунт в **GreenGamePay** — сервис
[пополнистим.рф](https://xn--h1aahgceagbyl.xn--p1ai/). После регистрации в личном
кабинете вы получите логин/пароль и **TON-адрес для пополнения баланса** — их и
впишете в `.env`.

Как это работает: покупатель платит в TON на ваш адрес пополнения GGP → ваш баланс
GGP растёт → бот видит средства (`check_balance`) и выдаёт звёзды через `buyStars`.
Средства всегда приходят вам, поэтому выдача идёт **по факту баланса**, а не по
сканированию сети: старейший неоплаченный крипто-заказ выдаётся первым (FIFO).

Чтобы добавить крипту как второй способ оплаты, впишите в `.env` и перезапустите
(`docker compose up -d`):

```dotenv
CRYPTO_ENABLED=true
GGP_USERNAME=ваш-логин-ggp
GGP_PASSWORD=ваш-пароль-ggp
GGP_TON_ADDRESS=TON-адрес-для-пополнения   # из вашего кабинета GGP
GGP_DEPOSIT_MEMO=ваш-логин-ggp             # комментарий к платежу
```

**Режим «только крипта» (без WATA).** Если у вас нет мерчанта WATA и вы хотите
принимать оплату только в TON — добавьте `CRYPTO_ONLY=true`. Тогда карта нигде не
показывается, а `WATA_TOKEN` можно оставить пустым:

```dotenv
CRYPTO_ENABLED=true
CRYPTO_ONLY=true
WATA_TOKEN=
GGP_USERNAME=ваш-логин-ggp
GGP_PASSWORD=ваш-пароль-ggp
GGP_TON_ADDRESS=TON-адрес-для-пополнения
```

Экономику крипто-оплаты см. в [docs/ECONOMICS.md](docs/ECONOMICS.md).

### Что-то пошло не так?

- **Смотрим логи:** `docker compose logs -f bot`.
- **Бот не стартует** → чаще всего не заполнен `WEBHOOK_HOST`. Проверьте, что домен
  открывается по `https://` в браузере (значит, Caddy выдал сертификат).
- **В боте нет ответа** → убедитесь, что порты 80/443 открыты и A-запись домена
  указывает на IP сервера.
- **Оплата не проходит** → проверьте `WATA_TOKEN` и что URL вебхука WATA указан
  верно (шаг 10). Частые ошибки — в разделе [❓ FAQ](#-faq).

## ⚙️ Конфигурация

не попадают.

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота от [@BotFather](https://t.me/BotFather) |
| `WATA_TOKEN` | да* | Токен мерчанта из ЛК WATA (*можно пустым при `CRYPTO_ONLY=true`) |
| `WATA_BASE_URL` | — | База Digital Goods API (по умолчанию `https://dg-api.wata.pro/api`) |
| `WATA_PUBLIC_KEY_URL` | — | URL публичного ключа WATA для проверки подписи вебхука |
| `MARKUP_PERCENT` | — | Наценка над `minPrice` в % (карта/WATA), итог клампится до +50% (по умолч. `20`) |
| `AUTO_CONFIRM` | — | `true` — авто-подтверждение выдачи звёзд после оплаты |
| `CRYPTO_ENABLED` | — | `true` — включить второй способ оплаты: крипта (TON) через GreenGamePay |
| `CRYPTO_ONLY` | — | `true` — режим «только крипта»: карта (WATA) не показывается, `WATA_TOKEN` не нужен (требует `CRYPTO_ENABLED=true`) |
| `CRYPTO_MARKUP_PERCENT` | — | Наценка для оплаты криптой в % (своя, обычно ниже карточной; без клампа +50%) |
| `GGP_USERNAME` / `GGP_PASSWORD` | для крипты | Доступ к GreenGamePay (только через `.env`) |
| `GGP_BASE_URL` | — | База API GGP (по умолч. `пополнистим.рф` в IDNA-форме) |
| `GGP_TON_ADDRESS` | для крипты | TON-адрес для пополнения баланса GGP (из ЛК GreenGamePay) |
| `GGP_DEPOSIT_MEMO` | — | Комментарий к платежу = ваш логин GGP (по умолч. `evansvl`) |
| `TON_POLL_INTERVAL` | — | Интервал проверки баланса GGP в секундах (по умолч. `20`) |
| `CRYPTO_PAYMENT_TTL_MIN` | — | Срок действия выставленной TON-суммы в минутах (по умолч. `30`) |
| `ADMIN_IDS` | — | Telegram ID администраторов через запятую (для `/stats`) |
| `DATABASE_URL` | — | DSN PostgreSQL (в compose уже настроен на сервис `postgres`) |
| `REDIS_URL` | — | DSN Redis (в compose настроен на сервис `redis`) |
| `WEBHOOK_HOST` | **да** | Публичный домен за вашим reverse proxy (напр. `bot.example.com`) — без него бот не стартует |
| `WEBHOOK_PORT` | — | HTTP-порт webhook-сервера внутри контейнера (по умолч. `8080`) |
| `WEBHOOK_PATH` | — | Путь вебхука WATA (по умолч. `/wata/webhook`) |
| `WEBHOOK_SECRET` | — | Доп. секрет: сверяется в заголовке `X-Webhook-Secret`, если задан |
| `TELEGRAM_WEBHOOK_PATH` | — | Путь вебхука Telegram (по умолч. `/tg/webhook`) |
| `TELEGRAM_WEBHOOK_SECRET` | — | Секрет заголовка `X-Telegram-Bot-Api-Secret-Token`; если пусто — генерируется из `BOT_TOKEN` |
| `LOG_LEVEL` | — | `DEBUG` / `INFO` / `WARNING` / `ERROR` |

### Где взять токены

- **`BOT_TOKEN`** — напишите [@BotFather](https://t.me/BotFather) → `/newbot` → скопируйте токен.
- **`WATA_TOKEN`** — личный кабинет мерчанта WATA: [merchant.wata.pro](https://merchant.wata.pro/login)
  (sandbox: [merchant-sandbox.wata.pro](https://merchant-sandbox.wata.pro/), доступ выдаёт менеджер WATA).

### Как считается цена

```
amount = minPrice × count × (1 + MARKUP_PERCENT / 100)
```

Итог жёстко клампится в диапазон, который требует WATA:

```
minPrice × count  ≤  amount  ≤  minPrice × count × 1.5   (максимум +50%)
```

Ваш доход = `amount − price − commission` (закупочная цена и комиссия WATA приходят
в ответе на создание заказа и сохраняются в БД как `margin`).

**Крипта (TON через GGP)** — отдельный способ оплаты со своей наценкой, без клампа
WATA. GGP отдаёт оптовую цену `{ton, rub}` за количество; покупатель платит
`ton × (1 + (CRYPTO_MARKUP_PERCENT + наценка_партнёра) / 100)`, округлённую вверх.
Покупатель шлёт TON на ваш адрес пополнения GGP и жмёт «✅ Я оплатил». Выдача идёт
**по факту баланса GGP**, а не по сканированию сети: бот проверяет `check_balance`, и
как только на балансе есть средства — выдаёт старейший неоплаченный крипто-заказ
через GGP `buyStars` (FIFO). Тот же фоновый воркер добивает заказы, если покупатель
не нажал кнопку. Если оплата прошла, а звёзды не дошли — в боте предлагается написать
в поддержку **@nnstorecontactbot**. Подробнее — в [docs/ECONOMICS.md](docs/ECONOMICS.md).

## 🌐 Reverse proxy и HTTPS

Webhook-сервер внутри контейнера слушает **обычный HTTP** на `127.0.0.1:8080`
(порт из `WEBHOOK_PORT`) и обслуживает **все** пути одним приложением: вебхук
Telegram (`TELEGRAM_WEBHOOK_PATH`, по умолч. `/tg/webhook`), вебхук WATA
(`WEBHOOK_PATH`, по умолч. `/wata/webhook`), вебхуки партнёрских ботов
(`/partner/{token}`) и `/health`. Поэтому достаточно
проксировать весь домен на `127.0.0.1:8080` — отдельные `location` для каждого пути
не нужны. TLS-терминацию и публикацию наружу вы настраиваете **сами**, вне
`docker-compose`. Ниже — два варианта на выбор; в обоих **замените `bot.example.com`
на свой домен**.

### Вариант 1 — Caddy (проще, авто-TLS)

Caddy сам получает и продлевает сертификат Let's Encrypt — больше ничего делать
не нужно. Добавьте в ваш `Caddyfile`:

```caddyfile
bot.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

```bash
sudo systemctl reload caddy
```

### Вариант 2 — Nginx (если nginx уже стоит)

Начните с **HTTP-блока на порту 80** — это вход для плагина certbot:

```nginx
server {
    listen 80;
    server_name bot.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Затем выпустите сертификат через certbot (Let's Encrypt):

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d bot.example.com
```

> ℹ️ Порт 80 здесь — это **исходный** блок. `certbot --nginx` сам перепишет его:
> добавит `listen 443 ssl` с путями к сертификату и редирект 80 → 443. Итоговый
> рабочий вебхук будет на **HTTPS (443)** — Telegram принимает вебхуки только по
> HTTPS. Если предпочитаете прописать TLS вручную, используйте `listen 443 ssl;`,
> директивы `ssl_certificate`/`ssl_certificate_key` и отдельный 80-й блок с
> `return 301 https://$host$request_uri;`.

Для выпуска сертификата нужны **открытые порты 80/443** и **A-запись домена** на
ваш сервер. Автопродление certbot настраивает сам (systemd-таймер `certbot.timer`);
проверить можно командой `sudo certbot renew --dry-run`.

## 🪝 Вебхуки (Telegram и WATA)

Бот работает в webhook-режиме: один HTTP-сервер принимает обновления от обоих сервисов.

### Telegram

Регистрировать вебхук вручную **не нужно** — при старте бот сам вызывает
`setWebhook` на `https://<WEBHOOK_HOST><TELEGRAM_WEBHOOK_PATH>` (по умолчанию
`https://bot.example.com/tg/webhook`) и удаляет его при остановке. Каждое обновление
проверяется по секрету `X-Telegram-Bot-Api-Secret-Token`: если `TELEGRAM_WEBHOOK_SECRET`
пуст, секрет детерминированно выводится из `BOT_TOKEN`. Главное — чтобы `WEBHOOK_HOST`
был корректным и домен был доступен по HTTPS снаружи.

### WATA

В личном кабинете WATA (раздел терминала/уведомлений) укажите URL вебхука:

```
https://<ваш-домен><WEBHOOK_PATH>      напр. https://bot.example.com/wata/webhook
```

Бот проверяет подпись `X-Signature` (RSA SHA-512) по публичному ключу WATA, логирует
весь payload и затем **сверяет статус заказа через `GET /stars/order/{id}`** — то есть
истинным источником считается ответ API, а не тело уведомления. GET к WATA лимитирован
(1 запрос / 30 c на объект), поэтому поллинг используется только как fallback.

> 📜 Логи в Docker — человекочитаемые (`docker compose logs -f bot`):
> `2026-06-19 12:00:00 INFO     app.main: telegram webhook set url=...`.

## 📦 Статусы заказа

```
Pending  →  Review  →  Paid / Refunded  →  Success / Fail
ожидает     ждёт        оплачен/возврат      исполнен/ошибка
оплаты      подтвержд.
```

- **Pending** — ссылка создана, ждём оплату.
- **Review** — оплачено, ждёт подтверждения мерчантом. При `AUTO_CONFIRM=true`
  бот сразу вызывает `confirm` → **Paid**.
- **Paid** — подтверждён, звёзды выдаются. **Success** — звёзды доставлены.
- **Refunded** — заказ отклонён, деньги возвращены плательщику. **Fail** — сбой выдачи.

## ❓ FAQ

**Как сделать бота для продажи звёзд Телеграм?**
Это и есть готовый open-source шаблон такого бота. Разверните его на своём сервере по
[пошаговому гайду](#-установка-по-шагам-для-новичков): создайте бота в BotFather,
получите токен WATA, заполните `.env`, поднимите HTTPS — и магазин звёзд готов.
Наценку вы задаёте сами (`MARKUP_PERCENT`), звёзды выдаются автоматически после оплаты.

**Это готовый скрипт/шаблон или нужно дописывать код?**
Готовый к запуску проект: приём оплаты (карта/СБП/крипта TON), автоматическая выдача
звёзд, реферальная программа, партнёрские боты и админ-панель уже внутри. Нужны только
сервер, домен и токены (BotFather + WATA). Код открытый — при желании допиливайте под себя.

**Можно ли продавать звёзды за криптовалюту (TON)?**
Да. Помимо оплаты картой/СБП через WATA, есть второй способ — крипта (TON) через
GreenGamePay со своей, более низкой наценкой (`CRYPTO_MARKUP_PERCENT`). Как включить —
см. блок «(Опционально) Оплата криптой (TON)» в гайде по установке.

**Оплата прошла, но звёзды не пришли.**
Бот уведомляет об оплате автоматически по вебхуку WATA — отдельной кнопки проверки нет.
Если уведомление не пришло, проверьте, что вебхук WATA указывает на
`https://<домен><WEBHOOK_PATH>` и этот адрес доступен снаружи
(`docker compose logs -f bot` покажет входящие уведомления). WATA лимитирует
`GET /stars/order` (1 запрос / 30 c на заказ), поэтому при недоступности этого запроса
бот берёт статус прямо из тела вебхука.

**Ошибка `STR_1002` при вводе получателя.**
Такого Telegram-аккаунта WATA не нашёл. Проверьте @username (без `@`, 5–32 символа).

**Ошибка `STR_1003`.**
Количество звёзд вне диапазона 50–50 000.

**Как изменить наценку?**
Поменяйте `MARKUP_PERCENT` в `.env` и перезапустите: `docker compose up -d`.
Помните про потолок +50% — большее значение всё равно заклампится.

**Нужен ли депозит в WATA?**
Нет. Используется продукт «Telegram Stars + Эквайринг»: клиент платит по ссылке,
звёзды выдаёт WATA, ваша прибыль — заложенная маржа.

**Как сменить язык бота?**
Кнопка «🌐 Язык / Language» в меню. Выбор сохраняется per-user;
при первом входе язык определяется по `language_code` Telegram (по умолчанию русский).
